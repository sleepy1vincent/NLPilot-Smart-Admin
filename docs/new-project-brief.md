## 1. 一句话定位

> **一个 AI 直接控制生产的系统：人看得见它在做什么，能随时喊停，能回退。**

不是"带对话框的管理后台"，是**AI 作为操作层**。

---

## 2. 为什么换题（背景，供你理解取舍）

旧项目是"商品管理系统 + AI 助手"，结论是：**CRUD 配不上 agent**——
查库存、改价格这些用表单更快，agent 只是把它包了一层。

新场景选**生产调度**，因为它是天然的多步任务：

```
接到订单 → 查物料库存 → 查设备产能 → 排产 → 下工单 → 占用物料
```

第二步的参数来自第一步的结果，**按钮做不了，必须由 agent 跑**。

## 3. 四条硬性需求（来自导师，不可删改）

| # | 需求 | 我的理解 |
|---|---|---|
| 1 | 企业级数据量 + **用 RAG 防幻觉** | 数据量上到几千~几万条；RAG 要能溯源、能拒答 |
| 2 | AI 控制可视化，**不是黑盒** | 左侧控制区，右侧 AI 操控区；随叫随停；保留现场 |
| 3 | 不是管理系统，是 **AI 控制生产** | 领域换成订单/工单/物料/设备 |
| 4 | **不要大对话框** | 改成一个控制入口（命令条 / 语音） |

## 4. 防幻觉架构（必须实现的四层，照抄旧项目经验）

### 核心原则

> **不判断模型说没说谎，而是让它没有说谎的通道。**

### 第 1 层：事实只能来自工具

- 模型不能直接写数据库，只能调工具
- 工具返回值是**唯一**事实来源（含 `affected` / `rowcount`）
- 判据：`tool_calls` 为空 ⇒ 本次没有任何数据库变更（直接推论，不做文本判断）

### 第 2 层：没调工具就不许说话

模型只能三选一：

| 情况 | 出口 | 约束 |
|---|---|---|
| 能做 | 调业务工具 | —— |
| 缺信息 | `clarify(slots="工单号,数量")` | 只能填**名词短语**，填不出句子 |
| 做不到 | `refuse(reason="...")` | 只能选**枚举** |

**所有展示给用户的句子由模板渲染，模型只填参数。**

`executed == 0` 时，模型生成的文字**一律丢弃**，换固定兜底。

### 第 3 层：双通道渲染

| 通道 | 内容 | 前端表现 |
|---|---|---|
| `result` | 工具返回值 | 事实卡片，标注来源（DB / 检索 / 联网） |
| `reply` | 模板话术 / 多步总结 | 文字，**旁边必须挨着卡片** |

有事实时不允许模型复述数字（单步 `reply=""`）。

### 第 4 层：数值不让模型算

| 场景 | 做法 |
|---|---|
| "第 N 个" | 工具加 `nth`，SQL `OFFSET` 直接取 |
| 日均/周转/合计 | 代码算好放进返回值（`daily_sold` / `days_left` / `total`） |
| 多名并列查询 | 代码拆名分别查再合并 |

**判据：一件事用提示词试两次还不稳，就说明不该交给模型。**

### RAG 防幻觉的正确形态（三步缺一不可）

| 环节 | 做法 | 缺了会怎样 |
|---|---|---|
| 检索 | 向量召回 + **元数据过滤**（品类/状态/时间） | 召回不相关文档 |
| 引用 | 每条结论带 `source`（文档 id + 段落） | 用户无法核对 |
| 拒答 | 分数低于阈值就明说"没有依据" | 拿不相关文档硬编 |

> ⚠️ 只有检索、没有引用和拒答，RAG 会让幻觉**更可信**——它现在"有理有据地错"。

## 5. 功能范围

### P0（没有就不算做完）

1. **订单 → 排产** 的多步闭环（至少 3 步，参数跨步传递）
2. **防幻觉四层**全部落地（第 1~4 层，缺一层不算）
3. **右侧行动流**：每一步"调了什么工具、参数是什么、结果是什么"实时可见
4. **左侧高亮**：AI 动哪条数据，左侧对应行高亮（延迟 < 500ms）
5. **可中断**：点停止后不再发起新动作，已执行的记录保留
6. **评测脚本**：可复现，一条命令跑完，输出通过率与失败明细

### P1（加分）

7. 回滚最近 N 步（补偿事务）
8. 命令入口（Ctrl+K）+ 语音输入
9. RAG 引用可点击跳转到原文

### P2（有时间再做）

10. 多用户 / 权限
11. 流式输出（SSE）把行动流做成实时

## 6. 数据要求

| 项 | 要求 |
|---|---|
| 体量 | 商品/物料 ≥ 5,000 条；订单 ≥ 2,000 条；工单 ≥ 5,000 条 |
| 文档 | ≥ 200 篇（作业规范/工艺手册/设备说明），供 RAG 使用 |
| 来源 | 优先公开数据集；找不到就**合成**，但必须能说清分布（品类、价格、销量服从什么规律） |
| 可复现 | 生成脚本固定随机种子，一条命令重造全库 |

**数据模型至少包含**：`order`（订单）/ `work_order`（工单）/ `material`（物料）/ `machine`（设备）。

## 7. UI 要求

```
┌──────────────┬───────────────────────────┐
│  控制区       │   AI 操控区                │
│  （人操作）    │  （AI 动作流 + 结果）        │
│              │                           │
│  订单表       │  ▶ 查询工单 WO-1024        │
│  物料表       │  ▶ 校验物料 M-07 库存       │
│  设备表       │  ▶ 生成排产方案（3 步）      │
│              │  [停止] [回退一步]          │
└──────────────┴───────────────────────────┘
```

硬性要求：

- **没有大对话框**。输入 = 顶部命令条（Ctrl+K）/ 语音
- AI 的输出**直接作用在左侧界面**：高亮行、填充字段、跳转定位
- 每一步动作**可读**：工具名 + 参数 + 结果条数
- 停止按钮**真的能停**（不是只改前端状态）

## 8. 技术约束

| 约束 | 说明 |
|---|---|
| 后端 | Python + Flask（沿用旧项目结构：routes → services → dao） |
| 模型 | 本地 Ollama / qwen2.5（7B 起步），不假设有大模型 |
| 数据库 | MySQL 8 + 连接池 + 事务 |
| 向量库 | ChromaDB（或等价方案），必须支持元数据过滤 |
| 单步/多步 | 同一套代码，`max_steps` 参数化；默认单步可降级 |
| 可观测 | 每个动作有 `trace`（step / tool / args / ok / 结果条数） |

## 9. 验收标准（必须可测）

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 无工具调用时不得出现业务数据 | 评测集 100% 通过（给了"在吗""谢谢"这类输入） |
| 2 | 模型文字不得直出 | 界面上的每句话要么来自模板，要么来自工具返回值 |
| 3 | RAG 结论必须带 source | 抽查 20 条，来源齐全率 ≥ 95% |
| 4 | RAG 拒答 | 检索分数低于阈值时，必须答"没有依据"，不得编 |
| 5 | 数值正确 | 名次/合计/周转类问题，代码算与人工核对一致 100% |
| 6 | 可中断 | 点停止后 ≤ 1s 不再发起新动作，日志保留 |
| 7 | 可视化延迟 | AI 动作到左侧高亮 ≤ 500ms |
| 8 | 评测可复现 | 一条命令跑完 ≤ 3 分钟，输出通过率 |

## 10. 明确不做

| ❌ | 原因 |
|---|---|
| 保留旧项目界面再叠新功能 | 会变成两套系统 |
| 在几十条数据上做优化 | 数据量要换，优化白费 |
| 用正则判断模型是否在说谎 | 换说法就漏，实测 190 条规则也不够 |
| 让另一个模型当幻觉审核员 | 实测无证据 45%、带证据 55%，比正则还差 |
| 一开始就做回滚 | 补偿事务最容易做错，放最后 |
| 开放"自由对话" | 一旦放开，前面所有约束都会被绕过 |

## 11. 与我协作的规则（重要，防止你乱改）

1. **改动前先给清单**：要改哪几个文件、每个改多少行、为什么。我说可以再动手。
2. **只改我指定的地方**。需要连带改别处，先报告，不要顺手改。
3. **不加注释、不改 docstring、不调排版**，除非我明确要求。
4. **不引入新依赖**，除非先说明理由和替代方案。
5. **每次改动附验证方式**：怎么复现、看什么指标。
6. **不跑长流程验证**（超过 1 分钟的评测）除非我要求；日常用 3~5 条快速自检。
7. **诚实优先**：做不到就说做不到，不确定就说不确定。**不要编**——这跟第 4 章是同一个要求。

## 12. 第一周只做三件事（建议起点）

1. **定数据模型**：4 张表 + 一份合成数据生成器（种子固定，可重跑）
2. **跑通一条最小链路**：`命令入口 → 一个工具 → 结果贴回界面`
3. **搭评测骨架**：10 条用例开始，覆盖"该调工具/不该调工具/该拒答"

**先跑通再谈架构。** 不要第一天就开始设计可回滚。
